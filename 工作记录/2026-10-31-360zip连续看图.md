# 工作记录 · 2026-10-31 · 360zip 国际版压缩包内连续看图

## 一、目标

1. 让 360 Zip 国际版里打开的压缩包图片能**连续翻页**（当前只能一张一张点开）。
2. 做成**插件**形态，且 **360zip 升级后不失效**。

## 二、前期逆向（已完成，详见 README 第二节）

### 2.1 摸清 360zip 图片模式

实测双击压缩包内图片后：

- 新建 `%TEMP%\360zip$Pic\360$N\`（序号递增，不复用）
- 只解压**当前这一张**进去
- 写 `config.ini`（UTF-16LE + BOM），内含 `[files]` 全清单、`[param] current`、`handle`（360zip 主窗口 HWND）
- 用 `ShellExecuteW` 按文件关联打开该单张图

### 2.2 根因

默认看图器 **2345 看图王**不解析 360zip 的 `[files]/[param]` 协议，只扫描同目录兄弟文件。
`360$N` 目录里只有 1 张，于是永远显示 `第1/1张`。

对照：图片恰好在源目录（8 张）时，看图王显示 `第1/8张` —— 证明它只会扫目录。

### 2.3 关键结论

360zip **不硬编码看图器**（全量字符串扫描：`2345` 只出现在字符表 `0123456789` 里），
走 `ShellExecuteW` + 文件关联 → **换关联即可接管**。

## 三、实现过程

### 3.1 核心程序 ComicViewer.exe

- `src/ComicViewer.cs`：入口、模式判定、`config.ini` 解析、压缩包定位、转发
- `src/ComicForm.cs`：看图窗口、压缩包按需读取、外部解压器（7z/UnRAR）
- `src/Installer.cs`：文件关联接管 / 还原 / 状态

编译命令：

```bat
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /codepage:65001 ^
  /platform:anycpu /optimize+ ^
  /r:System.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll /r:System.Management.dll ^
  /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll ^
  /out:dist\ComicViewer.exe src\ComicViewer.cs src\ComicForm.cs src\Installer.cs
```

> `/codepage:65001` 必须加，否则中文源码按 GBK 读会报错。

### 3.2 踩坑记录

#### 坑 1：PEB 读进程命令行失败

- 现象：能拿到 PEB 地址，但读出的"命令行长度"是 7950，指针是垃圾值。
- 排查：dump `PEB+0x10` 指向的内存，发现开头是 `4D 5A`（MZ 头）——那是 `ImageBase`，不是 `RTL_USER_PROCESS_PARAMETERS`。
- 结论：WOW64 下该结构偏移不可靠。
- 修复：
  1. `UNICODE_STRING.Buffer` 偏移纠正（x86 是 +4，不是 +8）
  2. **主路径改为 WMI**：`SELECT CommandLine FROM Win32_Process WHERE ProcessId=N`
  3. PEB 保留为兜底

WMI 需要引用 `System.Management.dll`。

#### 坑 2：程序起不来，只弹"请选择压缩包"

- 根因就是坑 1：定位失败后走 `OpenFileDialog` 兜底，窗口被模态框挡住。
- 修复坑 1 后即恢复正常。

#### 坑 3：小图不放大

`fit` 缩放里写了 `if (scale > 1) scale = 1`，600×900 的图在大窗口里只显示原尺寸。
改为上限 4 倍。

#### 坑 4：重复安装 → "原看图器"指向自己（自噬死循环）

- 现象：把成品从 `dist\` 换到项目根目录后重跑 `--install`，
  备份里出现 `viewer=E:\360zip连续看图\dist\ComicViewer.exe`（它自己）。
- 根因：第二次 install 时 `HKCU\...\shell\open\command` 已经是本程序，
  代码把"当前值"当成"原值"记录，覆盖了真正的 2345 路径。
- 后果：转发普通图片时会启动自己 → 递归。
- 修复三处：
  1. `Installer` 记录 `viewer` 时用 `IsSelf()` 跳过自身，且只在缺失时写入；
  2. 已存在但指向自己时，从 `assoc:` 备份条目里自动恢复（自愈）；
  3. `Program.Forward` 加 `IsSelf` 防呆，绝不自调用。
- 验证：重新 install 后 `viewer=D:\D\2345pic\2345PicViewer.exe`，
  打开 `img14.jpg` → 2345 正常打开，`ComicViewer` 进程数 0。

### 3.3 接管方案（更新免疫的核心）

Windows 关联链路：

```
.png → UserChoice(HKCU, 带哈希保护) → ProgID(2345Pic.png) → shell\open\command
```

- `UserChoice` **不能碰**（哈希校验，硬改会被系统重置）
- `HKCU\Software\Classes\<ProgID>\shell\open\command` **可以改**，且优先于 HKLM

只改这一层，把原命令备份到 `ComicViewer.backup.ini`。

实测本机可接管的 ProgID：

| 扩展名 | ProgID | 结果 |
|---|---|---|
| .png | 2345Pic.png | ✓ 接管 |
| .jpg | 2345Pic.jpg | ✓ 接管 |
| .jpeg | 2345Pic.jpeg | ✓ 接管 |
| .dib | 2345Pic.dib | ✓ 接管 |
| .webp | 2345Pic.webp | ✓ 接管 |
| .gif / .bmp / .jpe / .jfif | AppX43hnxt... | ✗ 系统照片应用，无法覆盖 |
