# 工作记录：打通 360zip + 2345 压缩包内连续看图

日期：2026-10-31
项目：E:\360zip连续看图

## 一、问题

用户打开 `E:\本子2\[闇に蠢く (どくろさん)] ママさんバレーでママオナホ・開幕戦と決勝戦! [DL版].zip`
（83 张 .webp），双击后仍由 2345 打开，显示「第1/1张」，无法连续翻页。

用户明确要求：**必须打通 360zip + 2345 这一套流程**，不许绕道。

## 二、排查过程（按时间）

### 1. 观察 360zip 对 webp 的真实行为
- 双击 webp 后，360zip 解压到 `%TEMP%\360zip$Temp\360$N\`（**不是** 360zip$Pic），
  目录里只有 1 张图、**没有 config.ini**。
- 360zip **直接 CreateProcess** 拉起
  `"D:\D\2345pic\2345PicViewer.exe" "<临时目录>\001.webp"`，
  **不走 ShellExecute / 文件关联**。

### 2. 关联劫持全部无效（逐一实测）
| 位置 | 结果 |
|---|---|
| HKCU\Software\Classes\2345Pic.webp\shell\open\command | 改成 ComicViewer，360zip 仍拉 2345 |
| HKLM\Software\Classes\2345Pic.webp\shell\open\command | 同上，无效 |
| HKCR（合并视图） | 已是 ComicViewer，360zip 视而不见 |
| HKLM\Software\WOW6432Node\Classes\2345Pic.webp | 键不存在 |
| HKCR\SystemFileAssociations\.webp | 不存在 |
| HKCU\Software\360zip\FileAssoc | 372 个键，全是压缩包扩展名，**无 .webp** |
| HKLM\Software\2345Pic | 只有 Capabilities\FileAssociations，无路径 |

- `AssocQueryString(ASSOCSTR_EXECUTABLE/COMMAND, ".webp")` 在 **64 位和 32 位 PowerShell 下都返回 ComicViewer**。
- 全盘扫描 `D:\D\360zip` 所有 exe/dll/dat（ASCII+UTF16 找 `2345Pic`/`PicViewer`/`2345pic`）→ **零命中**，排除硬编码。
- 把 `2345PicViewer.exe` 改名后双击 webp → **360zip 完全静默无反应**（不报错、不回退），
  证明它死认这个 exe。

**结论：360zip 用了一条既不走注册表 command、也不硬编码的路径去拉起 2345，无法从源头修改。**

### 3. 破局：IFEO 劫持
`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\2345PicViewer.exe`
的 `Debugger` 指向 `E:\360zip连续看图\ComicViewer.exe`。

实测生效，被调用时命令行变为：
```
"ComicViewer.exe" "D:\D\2345pic\2345PicViewer.exe" "<真实图片路径>"
```

### 4. 踩坑：IFEO 指向了旧 exe
- IFEO 指向项目根目录的 `ComicViewer.exe`，但编译输出到 `dist\ComicViewer.exe`。
- 根目录那份是旧版本（无日志、无 .real.exe 转发），表现为「进程秒退、无日志」，
  并且转发时又去启动 2345 → 再被 IFEO 拦 → 出现多个 ComicViewer 进程。
- **修法：每次编译后把 dist\ComicViewer.exe 复制到根目录。**

### 5. 核心突破：GDI+ 不支持 webp
- 自研 ComicViewer 用 `Image.FromStream` 解 webp → **「解码失败，参数无效」**。
- .NET Framework 4.8 的 GDI+ 在 Win10 上**不支持 WebP**（WIC 才有）。
- 用户明确要求：**不要另找方法，必须打通 360zip + 2345**。

### 6. 验证 2345 的「同目录兄弟文件」翻页
把 83 张 webp 解压到同一目录，用 `2345PicViewer.real.exe` 打开 001：
```
001.webp（1280×1807像素, 167KB）- 看图王 - 第1/83张 75%
```
**2345 认同目录多图并翻页 —— 方案成立。**

## 三、最终方案（已实现并验证）

```
360zip 双击 webp
   → 解压 1 张到 %TEMP%\360zip$Temp\360$N\
   → 启动 2345PicViewer.exe（被 IFEO 劫持）
   → ComicViewer 接管：
        1. 剥离 IFEO 参数，拿到真实图片路径
        2. 用 WMI 读 360zip 命令行，定位源压缩包
        3. 把压缩包内全部图片铺到 360zip$Temp\360$N\（同名同大小跳过）
        4. 启动 2345PicViewer.real.exe（原 2345 副本，避免再次被拦）
   → 2345 看到同目录 83 张，显示「第1/83张」，左右翻页正常
```

**实测结果**：
```
2345PicViewer.real  001.webp（1280×1807像素, 167KB）- 看图王 - 第1/83张 66%
```
日志：
```
普通启动: args=C:\...\360zip$Temp\360$0\001.webp
Handoff: archive=E:\本子2\...zip
Handoff: 铺图完成 82 张
Handoff: 启动 D:\D\2345pic\2345PicViewer.real.exe
```
临时目录 83 个文件。

## 四、代码改动

### src/ComicViewer.cs
1. **IFEO 参数剥离**：`args[0]` 以 `2345PicViewer.exe` 结尾时，取 `args[1]` 作为真实路径。
2. **加入 360zip$Temp 判定**：`inPicDir` 现在同时认 `360zip$Pic` 与 `360zip$Temp`。
3. **HandoffTo2345(path)**：新增。定位压缩包 → `ExtractAllImages` 铺图 → 启动 `.real.exe`。
4. **ExtractAllImages(archive, targetDir)**：新增。zip 走 ZipArchive 逐条解压；
   rar/7z 走 `External.ExtractAll` 缓存后复制。同名同大小跳过，避免重复解压。
5. **IsGdiPlusImage(name)**：新增。判断 GDI+ 能否解码，webp 等返回 false → 直接走 2345。
6. **ArchiveFromRunning360zip()**：新增。遍历 360zip 进程读命令行取压缩包路径。
7. **Forward()**：优先把原看图器替换为 `<原名>.real.exe`，避免 IFEO 死循环。
8. **Log(msg)**：新增诊断日志，写 `%TEMP%\ComicViewer.log`。

### src/Installer.cs
1. `Install()` 增加 IFEO 安装：把原 exe 复制为 `.real.exe`，写 `Debugger` 到 HKLM。
2. `Uninstall()` 增加 `RemoveIfeo()`。
3. `Status()` 增加 IFEO 状态显示。
4. 新增 `IfeoTarget` / `IfeoKeyPath` / `SetIfeo` / `RemoveIfeo` / `IfeoStatus`。
   - IFEO 需要管理员权限；失败时提示「请用管理员身份重新运行安装」。

## 七、已知限制

- **rar/7z 未真机验证**：本机没有 7-Zip / WinRAR，代码路径已写（走 `External.ExtractAll`）。
- IFEO 写入 HKLM 需要管理员权限，普通权限安装会提示失败。
- 2345 升级会覆盖 `2345PicViewer.exe`，但 `.real.exe` 与 IFEO 仍在，
  需要重新安装以刷新 `.real.exe`。
- 360zip 升级不影响本方案（未修改 360zip 任何文件、未依赖其临时目录结构以外的信息）。
